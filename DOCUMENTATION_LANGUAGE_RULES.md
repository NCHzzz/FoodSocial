# DOCUMENTATION_LANGUAGE_RULES.md

## Documentation Language Rule

- All project documentation files in Markdown (`.md`) must be written in English.
- Requirement interviews, discussions, clarification rounds, and working conversations may be conducted in Vietnamese.
- When Vietnamese input is provided, it must be normalized and documented in English in the final Markdown deliverables.
- If any example, note, placeholder, or draft is added to a project Markdown file, it must remain in English unless explicitly marked as a quoted user statement.

## Scope

This rule applies to all project documentation deliverables, including but not limited to:

- project overview
- business context
- personas and roles
- scope and MVP
- functional requirements
- non-functional requirements
- user flows
- domain model
- database design
- API and integration design
- architecture
- frontend structure
- backend structure
- backlog
- risks and open questions
- prompts prepared for AI code generation

## Working Agreement

- Interview language: Vietnamese is allowed.
- Documentation language: English is mandatory.
- If there is any conflict between conversation language and documentation language, the Markdown documentation must stay in English.
